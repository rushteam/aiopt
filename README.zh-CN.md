# AiOpt

[English](README.md) | 简体中文 | [日本語](README.ja.md) | [한국어](README.ko.md)

一个安全优先的 **Electron 桌面应用框架脚手架**。AiOpt 不是一个产品——它是从成熟 Electron
应用中提炼出来的可复用*基础组件*，并已端到端接好线，让你在一个值得信任的基础上开始真正的桌面应用，
而不必从零重建安全模型。

## 信任模型（核心所在）

AiOpt 围绕一条边界构建：

> **不可信的渲染进程 / 最小化的 preload / 特权主进程——而 IPC 就是授权边界。**

- **渲染进程**是一个 Web 上下文，应视为恶意输入。它不持有任何操作系统能力。
- **preload** 只暴露一个极小的、按用途命名的桥接接口——从不暴露原始的 `ipcRenderer`。
- **主进程**持有全部特权能力，只通过 IPC 处理器对外提供；这些处理器先**校验发送方**，再**在运行时校验载荷**
  （TypeScript 类型不是运行时检查）。

其余一切——作为主进程侧唯一关口的 CSP、Electron Fuses、失败即关闭（fail-closed）的导航守卫、
从不改写历史的 SQLite 迁移、分层配置、永不进入 Git 跟踪路径的密钥——都是为了让这条边界名副其实。

## 垂直切片

脚手架不堆砌功能。一个端到端的演示证明每个基础组件都真正接上了线：

> 渲染进程中的一个按钮 → 一个按用途命名的 preload 桥接方法 → 一个主进程 IPC 处理器：它先
> **断言发送方可信**，再**校验载荷**，然后写入 **SQLite（通过迁移）**，经由**统一的 IPC 错误协议**
> 回复，渲染进程再用**语义化 token（浅色 + 深色）**渲染结果——所有文案都经过 **i18n + 术语表**。

要添加真正的功能，照着这个切片的形状复制即可。它同时也是“实现与评审”清单的活样例。

## 基础功能（开箱即用）

每个桌面应用都需要同样一层与业务无关的外壳，所以 AiOpt 直接提供——每一块都接在同一条信任边界上
（可信发送方 + 运行时校验、失败即关闭的导航、永不到达渲染进程的密钥）：

- **应用菜单**——原生菜单，其命令词表（`shared/menuCommands.ts`）是唯一事实来源，被主进程（分发）、
  preload（白名单二次校验）和渲染进程（处理）共同复用。设置、检查更新、关于 会单向分发到渲染进程。
- **设置**——分区的设置外壳：外观、账户、快捷键、更新、关于。
- **外观 / 主题**——基于语义化 token 的 `system | light | dark`，浅色与深色**都**有取值；偏好通过分层配置
  存储持久化，并在首次绘制前生效（无闪烁），经由 CSSOM 应用（符合 CSP）。
- **账户（登录 / 登出）**——一个**可插拔的认证提供方**，附带本地桩实现。会话 token 只存放在操作系统加密的
  密钥存储中、使用仅主进程可用的键；渲染进程只看到安全的 `signed-in / signed-out` 状态，永远看不到 token。
- **快捷键**——同一份注册表（`shared/shortcuts.ts`）同时驱动原生菜单加速键和快捷键设置列表，二者不会走样。
- **更新**——一个**可插拔的更新提供方**，附带报告“已是最新”的本地桩实现。真正的更新路径被有意省略并且
  **受闸门管控**——见 `docs/dev-rules/updater.md`。
- **关于**——从主进程读取的应用 / Electron / Chrome / Node 版本。

把认证和更新提供方换成对接你自己后端的实现即可；管理器、IPC 接口面和 UI 都保持不变。

## 供应商路由——一个转换代理，多条路由

各个 Agent 的接口格式并不一致：Claude 使用 Anthropic Messages，Codex/Grok 使用 OpenAI Responses API，
其他则使用 OpenAI Chat Completions。AiOpt 让一个使用格式 **X** 的 Agent 绑定到任意使用格式 **Y**
的供应商——而 Agent 完全不知道中间发生过转换。

> **一个回环 HTTP 服务器，在一个临时的 `127.0.0.1` 端口上，转换所有跨格式绑定。不是每个供应商一个代理，
> 也不是每个方向一个——而是单个服务器，按每条绑定的路径 token 进行路由。**

- 每条绑定（一个 Agent → 一个供应商 + 模型）注册**一条路由**，以 **URL 路径中的不透明 token** 寻址：
  Agent 的配置指向 `http://127.0.0.1:<port>/<token>`，并追加它自己的原生后缀
  （`/v1/messages`、`/v1/chat/completions`、`/responses`）。
- 服务器剥离 token、查找路由，由**路由规格——而不是对请求体的任何嗅探——决定转换方向**。因此 `A→O`
  绑定和 `O→A` 绑定可以共存于同一端口，只靠各自的 token 区分。
- **N 个供应商、任意方向组合 ⇒ 1 个进程、1 个端口、N 条 token 路由。** 路由数量只取决于当前绑定了多少个
  Agent——与其他因素无关。

| 入站（Agent 使用）→ 出站（供应商使用） | 状态 |
| --- | --- |
| Anthropic → OpenAI Chat Completions | 已启用 |
| OpenAI Responses → OpenAI Chat Completions | 已启用 |
| OpenAI Responses → Anthropic（带推理桥接） | 已启用 |
| OpenAI Chat Completions → Anthropic | 预留 |

这同样沿用整体的信任模型。token 用于认证请求，并且**每次重新绑定都会轮换**（一旦绑定被重新指向、清除，
或应用重启，旧 token 立即失效）；Agent 的配置里只保存这个 token，从不保存真正的供应商密钥。**真正的密钥在
请求时于主进程侧解析**，并且只放入*出站*请求头。上游错误响应体从不转发（它们可能回显密钥）——调用方只会
收到一个通用的带错误码的信封——日志只记录方法 / 去除 token 后的路径 / 状态码 / 字节数，从不记录请求体、
请求头、token 或密钥。

## 安装与使用

macOS、Windows 和 Linux 的构建产物附在每个 [GitHub
Release](https://github.com/rushteam/aiopt/releases) 上，由打标签的提交在三个平台上分别构建：

| 平台 | 下载内容 | 安装方式 |
| --- | --- | --- |
| macOS | `.zip` | 解压后把 **AiOpt.app** 拖入 `/Applications`。 |
| Windows | `Setup.exe` | 直接运行；Squirrel 按用户安装，不弹管理员权限提示。 |
| Linux | `.zip` | 解压到任意位置，运行 `AiOpt` 可执行文件。 |

> **目前还没有发布任何版本**——在推送第一个 `v*` 标签之前，该页面是空的。在那之前，请从源码运行（见下文）。

### 构建产物未签名——请先阅读

目前还没有代码签名证书，所以 **macOS 和 Windows 在首次启动时都会拒绝运行该应用。** 这不是一个可以忽略的
警告，而是一道需要你刻意跨过的拦截，每次安装一次：

- **macOS**——首次双击会提示无法打开“AiOpt”，因为无法验证开发者。关闭提示后，**右键（或按住 Control 点按）
  应用 → 打开**，并在第二个对话框中确认。关键在于右键 → 打开：它与双击走的是不同的代码路径，正是它让你通过。
  如果 macOS 仍然拒绝，打开**系统设置 → 隐私与安全性**，滚动到关于 AiOpt 的提示，点击**仍要打开**。
- **Windows**——SmartScreen 会显示蓝色的“Windows 已保护你的电脑”界面。点击**更多信息**，然后点击**仍要运行**。
- **Linux**——不会拦截该应用。

只有在你信任文件来源时才这样做。恶意软件也会要求你执行同样的步骤，这正是签名之所以重要、以及这一节存在
而不是一句安慰话的原因。签名已在计划中——见 `docs/dev-rules/development-workflow.md` §6。

**macOS 构建仅支持 Apple Silicon（arm64）。** 发布用的 runner 是 `macos-latest`，即 arm64，所以暂时没有
Intel 版本。在 Intel Mac 上请从源码运行（见下文）。

### 首次运行

AiOpt 是面向 Agent CLI 的配置管理器和转换代理——它自身不会与模型通信。最短的可用路径：

1. **添加供应商**——供应商 → *添加供应商*。选择一个预设或选择自定义，粘贴 API 密钥，并列出你想用的模型。
   密钥存入操作系统加密的密钥存储，从不进入 Git 跟踪的文件。再次打开表单时显示的是“已保存密钥”而不是密钥
   本身——只有当你按下**显示**时它才会以明文出现，这是一个刻意设置、受闸门管控的例外，而不是应用平时读取
   密钥的方式。
2. **绑定 Agent**——每张 Agent 卡片选择一个供应商和模型。AiOpt 会改写该 Agent 自己的配置文件
   （`~/.claude/settings.json`、`~/.codex/config.toml`……），使其指向本地代理，因此 Agent 不需要任何参数，
   也不需要知道发生过转换。
3. **像往常一样使用 Agent。** 请求经过 `127.0.0.1`，在 Agent 与供应商的接口格式不一致时进行转换，并且只在
   出站这一段携带真正的密钥。

目前可识别九个 Agent CLI：Claude Code、Codex、Cursor、DeepSeek Harness、Gemini CLI、Grok、Hermes、
OpenCode 和 pi。其中八个可以绑定到供应商——Cursor 不行，因为它的 CLI 没有覆盖 base URL 的方式，所以它只出现
在技能同步中。

**AiOpt 会编辑属于其他工具的配置文件。** 它只写入 `shared/aiProviders.ts` 中为每个 Agent 列出的已知文件，
但这些文件可能正是你手动配置过的。绑定之前，先看看 Agent 卡片上说明它将修改什么。

### 从源码运行

这也是 Intel Mac 或任何没有附带构建产物的平台的途径。

```sh
pnpm install
pnpm dev                # open the app window
```

从源码运行时，数据与已安装的副本相互隔离，存放在 `AiOpt-dev` 而不是 `AiOpt` 中
（位于 `~/Library/Application Support`、`%APPDATA%` 或 `~/.config` 下）。它启动时没有任何供应商，
也从不读取或修改已安装应用的密钥。两者还可以同时运行。

贡献者还需要多做一步——`pnpm dco:install-hook` 会为每次提交自动加上 DCO 签署尾注（见下文的**闸门**）。

## 闸门

| 命令 | 检查内容 |
