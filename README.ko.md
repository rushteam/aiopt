# AiOpt

[English](README.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md) | 한국어

보안을 최우선으로 하는 **Electron 데스크톱 앱 프레임워크 스캐폴드**입니다. AiOpt는 제품이 아닙니다. 성숙한
Electron 클라이언트에서 재사용 가능한 *기본 요소*를 추출해 처음부터 끝까지 연결해 둔 것으로, 보안 모델을
처음부터 다시 만들지 않고도 신뢰할 수 있는 기반 위에서 실제 데스크톱 앱을 시작할 수 있게 해 줍니다.

## 신뢰 모델 (핵심)

AiOpt는 하나의 경계를 중심으로 만들어졌습니다.

> **신뢰하지 않는 렌더러 / 최소한의 preload / 권한을 가진 메인 — 그리고 IPC가 인가 경계입니다.**

- **렌더러**는 웹 컨텍스트입니다. 적대적인 입력으로 취급합니다. OS 기능은 전혀 갖지 않습니다.
- **preload**는 용도별로 이름 붙인 아주 작은 브리지만 노출합니다. 원시 `ipcRenderer`는 절대 노출하지 않습니다.
- **메인** 프로세스는 모든 권한 기능을 소유하고 IPC 핸들러를 통해서만 제공합니다. 핸들러는 먼저
  **발신자를 인가**한 다음 **페이로드를 런타임에 검증**합니다(TypeScript 타입은 런타임 검사가 아닙니다).

그 밖의 모든 것 — 메인 측 단일 관문으로서의 CSP, Electron Fuses, 페일 클로즈(fail-closed) 내비게이션 가드,
이력을 절대 다시 쓰지 않는 SQLite 마이그레이션, 계층형 설정, Git으로 추적되는 경로에 절대 닿지 않는 시크릿 —
은 이 경계를 정직하게 유지하기 위해 존재합니다.

## 수직 슬라이스

이 스캐폴드는 기능을 쌓아 올리지 않습니다. 하나의 엔드투엔드 데모가 모든 기본 요소가 실제로 연결되어 있음을
증명합니다.

> 렌더러의 버튼 → 용도별로 이름 붙인 preload 브리지 메서드 → 메인 IPC 핸들러. 핸들러는 **신뢰할 수 있는
> 발신자인지 확인**하고, **페이로드를 검증**한 뒤 **SQLite(마이그레이션을 통해)**에 기록하고, **통일된 IPC 오류
> 프로토콜**로 응답합니다. 렌더러는 결과를 **시맨틱 토큰(라이트 + 다크)**으로 렌더링하며, 모든 문구는
> **i18n + 용어집**을 거칩니다.

실제 기능을 추가하려면 이 슬라이스의 형태를 그대로 따라 하세요. "구현 및 리뷰" 체크리스트의 살아 있는
예시이기도 합니다.

## 기본 기능 (기본 제공)

모든 데스크톱 앱에는 업무와 무관한 같은 껍데기가 필요하므로 AiOpt가 이를 제공합니다. 각 부분은 같은 신뢰
경계(신뢰할 수 있는 발신자 + 런타임 검증, 페일 클로즈 내비게이션, 렌더러에 절대 도달하지 않는 시크릿)에
연결되어 있습니다.

- **애플리케이션 메뉴** — 네이티브 메뉴입니다. 명령 어휘(`shared/menuCommands.ts`)가 단일 진실 공급원이며
  메인(디스패치), preload(허용 목록 재검증), 렌더러(핸들러)가 함께 사용합니다. 설정, 업데이트 확인, 정보는
  렌더러로 단방향 디스패치됩니다.
- **설정** — 섹션으로 나뉜 설정 화면: 화면, 계정, 단축키, 업데이트, 정보.
- **화면 / 테마** — 시맨틱 토큰 위의 `system | light | dark`로, 라이트와 다크 값을 **모두** 가집니다. 설정은
  계층형 설정 저장소에 유지되며 첫 페인트 전에(깜빡임 없이) CSSOM을 통해 적용됩니다(CSP 준수).
- **계정 (로그인 / 로그아웃)** — **교체 가능한 인증 공급자**와 로컬 스텁 구현. 세션 토큰은 메인 전용 키로
  OS 암호화 시크릿 저장소에만 보관됩니다. 렌더러는 안전한 `signed-in / signed-out` 상태만 볼 수 있고 토큰은
  절대 보지 못합니다.
- **단축키** — 하나의 레지스트리(`shared/shortcuts.ts`)가 네이티브 메뉴 가속기와 단축키 설정 목록을 함께
  구동하므로 둘이 어긋날 수 없습니다.
- **업데이트** — **교체 가능한 업데이트 공급자**와 "최신 상태"라고 보고하는 로컬 스텁 구현. 실제 업데이트
  경로는 의도적으로 빠져 있으며 **게이트로 관리**됩니다 — `docs/dev-rules/updater.md`를 참고하세요.
- **정보** — 메인에서 읽어 온 앱 / Electron / Chrome / Node 버전.

인증 공급자와 업데이트 공급자를 여러분의 백엔드와 통신하는 것으로 바꾸기만 하면 됩니다. 매니저, IPC 인터페이스,
UI는 그대로입니다.

## 공급자 라우팅 — 하나의 변환 프록시, 여러 라우트

에이전트마다 통신 형식이 다릅니다. Claude는 Anthropic Messages를, Codex/Grok은 OpenAI Responses API를,
나머지는 OpenAI Chat Completions를 사용합니다. AiOpt는 형식 **X**를 사용하는 에이전트를 형식 **Y**를
사용하는 어떤 공급자에든 바인딩할 수 있게 해 줍니다 — 변환이 일어났다는 사실을 에이전트가 모르게.

> **하나의 루프백 HTTP 서버가 하나의 임시 `127.0.0.1` 포트에서 형식을 넘나드는 모든 바인딩을 변환합니다.
> 공급자마다 하나도, 방향마다 하나도 아닌 — 바인딩별 경로 토큰으로 라우팅하는 단일 서버입니다.**

- 각 바인딩(에이전트 하나 → 공급자 + 모델 하나)은 **라우트 하나**를 등록하며, **URL 경로 안의 불투명한 토큰**으로
  식별됩니다. 에이전트의 설정은 `http://127.0.0.1:<port>/<token>`을 가리키고, 여기에 자체 네이티브 접미사
  (`/v1/messages`, `/v1/chat/completions`, `/responses`)를 덧붙입니다.
- 서버는 토큰을 떼어 내고 라우트를 조회하며, **요청 본문을 추측하는 것이 아니라 라우트 명세가 변환 방향을
  결정합니다**. 그래서 `A→O` 바인딩과 `O→A` 바인딩이 같은 포트에서 공존하고, 토큰으로만 구분됩니다.
- **공급자 N개, 방향 조합은 자유 ⇒ 프로세스 1개, 포트 1개, 토큰 라우트 N개.** 라우트 수는 현재 바인딩된
  에이전트 수만 따라갑니다.

| 인바운드 (에이전트가 사용) → 아웃바운드 (공급자가 사용) | 상태 |
| --- | --- |
| Anthropic → OpenAI Chat Completions | 사용 |
| OpenAI Responses → OpenAI Chat Completions | 사용 |
| OpenAI Responses → Anthropic (추론 브리지 포함) | 사용 |
| OpenAI Chat Completions → Anthropic | 예약됨 |

이것도 다른 모든 것과 같은 신뢰 모델을 따릅니다. 토큰은 요청을 인증하며 **다시 바인딩할 때마다 교체**됩니다
(바인딩 대상이 바뀌거나, 해제되거나, 앱이 재시작되는 순간 이전 토큰은 무효가 됩니다). 에이전트의 설정에는 그
토큰만 들어 있고 실제 공급자 키는 절대 들어가지 않습니다. **실제 키는 요청 시점에 메인 측에서 조회**되어
*아웃바운드* 헤더에만 들어갑니다. 업스트림 오류 본문은 절대 전달하지 않으며(키를 그대로 되돌려 줄 수 있으므로)
클라이언트는 일반적인 오류 코드 봉투만 받습니다. 로그에는 메서드 / 토큰을 제거한 경로 / 상태 / 바이트 수만
기록하고, 본문, 헤더, 토큰, 키는 절대 기록하지 않습니다.

## 설치 및 사용

macOS, Windows, Linux용 빌드는 각 [GitHub
Release](https://github.com/rushteam/aiopt/releases)에 첨부되며, 태그가 붙은 커밋으로부터 세 플랫폼에서 각각
빌드됩니다.

| 플랫폼 | 다운로드할 파일 | 설치 방법 |
| --- | --- | --- |
| macOS | `.zip` | 압축을 풀고 **AiOpt.app**을 `/Applications`로 드래그합니다. |
| Windows | `Setup.exe` | 실행하면 됩니다. Squirrel이 사용자 단위로 설치하며 관리자 권한 확인이 뜨지 않습니다. |
| Linux | `.zip` | 원하는 위치에 압축을 풀고 `AiOpt` 바이너리를 실행합니다. |

> **아직 공개된 릴리스가 없습니다** — 첫 `v*` 태그가 푸시되기 전까지 그 페이지는 비어 있습니다. 그때까지는
> 소스에서 실행하세요(아래 참고).

### 빌드는 서명되지 않았습니다 — 먼저 읽어 주세요

아직 코드 서명 인증서가 없으므로 **macOS와 Windows 모두 첫 실행 시 앱을 거부합니다.** 이는 무시해도 되는 경고가
아니라, 설치할 때마다 한 번씩 의도적으로 넘어가야 하는 차단입니다.

- **macOS** — 처음 더블 클릭하면 "개발자를 확인할 수 없기 때문에 'AiOpt'을(를) 열 수 없습니다"라는 메시지가
  뜹니다. 이를 닫은 뒤 **앱을 오른쪽 클릭(또는 Control 키를 누른 채 클릭) → 열기**를 선택하고, 두 번째 대화 상자에서
  확인합니다. 중요한 것은 오른쪽 클릭 → 열기입니다. 더블 클릭과는 다른 코드 경로이며, 이것이 통과시켜 줍니다.
  그래도 macOS가 거부하면 **시스템 설정 → 개인정보 보호 및 보안**을 열고 AiOpt에 관한 메시지까지 스크롤한 뒤
  **확인 없이 열기**를 클릭합니다.
- **Windows** — SmartScreen이 파란색 "Windows의 PC 보호" 화면을 표시합니다. **추가 정보**를 클릭한 다음
  **실행**을 클릭합니다.
- **Linux** — 앱을 차단하지 않습니다.

파일을 받은 출처를 신뢰할 때만 이렇게 하세요. 악성 코드도 똑같은 절차를 요구합니다. 바로 그래서 서명이 중요하고,
안심시키는 한 문장 대신 이 섹션이 있는 것입니다. 서명은 계획되어 있습니다 —
`docs/dev-rules/development-workflow.md` §6을 참고하세요.

**macOS 빌드는 Apple Silicon(arm64) 전용입니다.** 릴리스 러너가 arm64인 `macos-latest`이므로 아직 Intel 빌드는
없습니다. Intel Mac에서는 소스에서 실행하세요(아래 참고).

### 처음 실행하기

AiOpt는 에이전트 CLI를 위한 설정 관리자이자 변환 프록시로, 스스로 모델과 통신하지는 않습니다. 가장 짧은 사용
경로는 다음과 같습니다.

1. **공급자 추가** — 공급자 → *공급자 추가*. 프리셋을 고르거나 사용자 지정을 선택하고, API 키를 붙여 넣은 뒤
   사용할 모델을 나열합니다. 키는 OS 암호화 시크릿 저장소에 들어가며 Git으로 추적되는 파일에는 절대 들어가지
   않습니다. 양식을 다시 열면 키 대신 "키가 저장됨"이 표시됩니다 — 키가 평문으로 다시 보이는 것은 **표시**를
   눌렀을 때뿐이며, 이는 앱이 평소 키를 읽는 방식이 아니라 의도적으로 둔, 게이트가 걸린 예외입니다.
2. **에이전트 바인딩** — 각 에이전트 카드에서 공급자와 모델을 고릅니다. AiOpt는 해당 에이전트 자체의 설정 파일
   (`~/.claude/settings.json`, `~/.codex/config.toml` 등)을 로컬 프록시를 가리키도록 다시 작성하므로, 에이전트에는
   플래그도 필요 없고 변환이 일어났다는 사실을 알 필요도 없습니다.
3. **에이전트를 평소처럼 사용합니다.** 요청은 `127.0.0.1`을 거치고, 에이전트와 공급자의 통신 형식이 다르면
   변환되며, 실제 키는 아웃바운드 구간에서만 전달됩니다.

인식되는 에이전트 CLI는 9개입니다: Claude Code, Codex, Cursor, DeepSeek Harness, Gemini CLI, Grok, Hermes,
OpenCode, pi. 이 중 8개는 공급자에 바인딩할 수 있습니다 — Cursor는 CLI에 base URL을 재정의하는 방법이 없어서
바인딩할 수 없고, 스킬 동기화에만 나타납니다.

**AiOpt는 다른 도구에 속한 설정 파일을 편집합니다.** `shared/aiProviders.ts`에 에이전트별로 나열된 알려진 파일에만
쓰지만, 그 파일은 여러분이 직접 설정해 두었을 수도 있는 바로 그 파일입니다. 바인딩하기 전에 에이전트 카드가 무엇을
바꾼다고 안내하는지 확인하세요.

### 소스에서 실행

Intel Mac이나 빌드가 첨부되지 않은 플랫폼에서도 이 방법을 사용합니다.

```sh
pnpm install
pnpm dev                # open the app window
```

소스에서 실행하면 데이터가 설치된 앱과 분리되어 `AiOpt`가 아닌 `AiOpt-dev`에 저장됩니다
(`~/Library/Application Support`, `%APPDATA%`, 또는 `~/.config` 아래). 공급자가 하나도 없는 상태로 시작하며,
설치된 앱의 키를 읽거나 바꾸지 않습니다. 둘을 동시에 실행할 수도 있습니다.

기여자는 한 단계가 더 있습니다 — `pnpm dco:install-hook`을 실행하면 모든 커밋에 DCO 서명 트레일러가 자동으로
붙습니다(아래 **게이트** 참고).

## 게이트

| 명령 | 검사 내용 |
| --- | --- |
| `pnpm test:unit` | 워크스페이스의 모든 단위 테스트(커밋 게이트). |
| `pnpm -r run --if-present typecheck` | 패키지별 타입 검사. |

| `pnpm check:version` | 두 매니페스트가 같은 버전을 명시하고 릴리스 태그와 일치하는지. |
