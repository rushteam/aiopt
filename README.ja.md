# AiOpt

[English](README.md) | [简体中文](README.zh-CN.md) | 日本語 | [한국어](README.ko.md)

**ひとつのプロバイダープールで、すべてのエージェント CLI を、あらゆる API フォーマットへ。**

AiOpt は、AI コーディングエージェントを、実際にトークン料金を払いたいモデルプロバイダーへルーティングする
デスクトップアプリです。プロバイダーはエンドポイント・キー・モデルを一度登録するだけ。あとはワンクリックで
Claude Code、Codex、Gemini CLI、OpenCode などの対応エージェントをそこへ向けられます。エージェントと
プロバイダーの API フォーマットが異なる場合は、AiOpt のローカルプロキシが間を変換します。Codex を Anthropic の
モデルで動かすことも、Claude Code を任意の OpenAI 互換エンドポイントにつなぐこともでき、フラグやラッパー、
環境変数を管理する必要はありません。

## AiOpt が解決すること

エージェント CLI はそれぞれ独自の設定ファイル、独自のキーの置き場所、独自の API フォーマットを持っています。
モデルを切り替えるたびに `~/.claude/settings.json` を手で編集し、次に `~/.codex/config.toml`、さらに別の場所の
YAML —— 同じキーをあちこちに貼り付けることになります。エージェントが話せないフォーマットのプロバイダーは、
そもそも使えません。

AiOpt はそれを、プロバイダーをまとめて管理する場所、エージェントごとのひとつの切り替え、そしてフォーマットの
違いを吸収する変換レイヤーに置き換えます。

## 機能

### プロバイダープール

- **一度登録すれば、どこでも再利用。** プロバイダーは名前、API フォーマット、ベース URL、キー、モデル一覧から
  成ります。すべてのエージェントが同じプールを使います。
- Anthropic、OpenAI、DeepSeek、Moonshot（Kimi）の**プリセット**、または任意のゲートウェイ・中継・セルフホストの
  エンドポイント向けの **カスタム…**。
- **モデルを読み込む** で、ID を手入力せずにプロバイダーのモデル一覧から直接取得できます。
- **エイリアス** を使うと、長いモデル ID の代わりに短い名前やエージェントに合った名前を書き込めます。
- **アップストリーム互換性** は、転送前に指定したトップレベルのリクエストフィールドを取り除きます。知らない
  パラメーターを無視せずに拒否する厳格なゲートウェイ向けです。

### ワンクリックでエージェントをバインド

認識されるエージェント CLI は 9 つです：**Claude Code、Codex、Cursor、DeepSeek Harness、Gemini CLI、Grok、
Hermes、OpenCode、pi**。そのうち 8 つはプロバイダーにバインドできます。Cursor の CLI はベース URL を上書き
できないため、スキルの同期にのみ参加します。

- エージェントカードでプロバイダーとモデルを選んで適用するだけ。AiOpt はエージェント**自身のネイティブな
  設定ファイル**に書き込むので、エージェントはこれまでとまったく同じように動きます —— ランチャーもシェルの
  エイリアスも不要です。
- **排他**型のエージェントは有効なプロバイダーが置き換えられ、**追加**型のエージェント（DeepSeek Harness、
  Hermes、OpenCode）はすべてのプロバイダーを並べて保持し、既定だけが切り替わります。
- どのファイルでも最初に書き込む前に、AiOpt は**元のファイル**を `<file>.aiopt.bak` として保存します。
  **デフォルトに戻す** でそのまま復元できます —— AiOpt が作成したファイルなら削除されます。
- **設定を表示** は、AiOpt が管理するファイルとその場所を一覧表示しますが、中身は決して表示しません
  （いくつかにはキーが含まれています）。

### フォーマット間変換プロキシ

| エージェントが話す → プロバイダーが話す | 状態 |
| --- | --- |
| Anthropic Messages → OpenAI Chat Completions | 有効 |
| OpenAI Responses → OpenAI Chat Completions | 有効 |
| OpenAI Responses → Anthropic Messages（推論ブリッジ付き） | 有効 |
| OpenAI Chat Completions → Anthropic Messages | 予約済み |

- **ループバックサーバーはひとつ、`127.0.0.1` のポートもひとつ、ルートはバインドごとにひとつ。** 各バインドは
  URL パスに不透明なトークンを持ち、リクエストボディからの推測ではなくルートが変換の方向を決めます。そのため
  逆方向のバインドが同じポートを共有しても干渉しません。
- **ストリーミングとツール呼び出しも変換**します。プレーンテキストだけではありません —— Server-Sent Events を
  双方向にイベント単位で組み直します。
- **推論ブリッジ** は、Claude の拡張思考ブロックとその署名をステートレスな Responses プロトコル越しに運びます。
  そのため Claude のモデルで動く Codex の複数ターンのセッションでも、推論が途切れません。
- **忠実に変換できないフィールドは、黙って捨てずに明確なエラーで拒否**します。エージェントが知らないうちに
  違う答えを受け取ることはありません。
- **再起動しても変わりません。** ポートとバインドごとのトークンは永続化されるため、すでに動いているエージェントは
  AiOpt の再起動後もそのまま使えます。バインドの向け先が変わった瞬間にトークンは入れ替わり、バインドを解除すると
  無効になります。他のプログラムがポートを使っている場合は **ポートを更新** で移動できます。

### プロキシモード

- **オフ（既定）：** 同じフォーマット同士のバインドは、エージェントをプロバイダーへ**直接**つなぎます。AiOpt が
  動いていなくても使い続けられます。エージェント自身がキーを送る必要があるため、プロバイダーのキーは
  エージェントの設定ファイルに書き込まれます。
- **オン：** すべてのバインドがローカルプロキシを経由します。エージェントの設定が持つのはループバックトークン
  だけになり、**本物のキーは AiOpt の暗号化ストアから出ません**。使用量も集計されます。エージェントがプロキシに
  依存している間は、AiOpt は終了前に確認します。
- フォーマットをまたぐバインドは常にプロキシを使い、Gemini のバインドは常に直接接続です。

### 使用状況

プロキシを通ったトラフィックについて、リクエスト数、成功率、入力 / 出力 / 合計トークンを集計し、日別のグラフと
**プロバイダー別・エージェント別・モデル別** の内訳を表示します。応答から読み取るのは数値の使用量フィールド
だけで、内容は決して読みません。

### スキルの同期

エージェントのスキルをひとつの**中央ライブラリ**（アプリのデータ内、または `~/.aiopt/skills`）にまとめ、各
エージェントのスキルディレクトリへ同期します。

- **取り込む ←** でエージェントのスキルをライブラリへ、**送り出す →** でライブラリの版をエージェントへ、
  **すべてのエージェントへ送り出す** で一度に配布できます。
- **差分** はファイル単位の変更を内容のプレビュー付きで表示し、**マージ** ではライブラリにどちらの版を残すかを
  ファイルごとに選べます。
- 上書きはすべてアトミックです。シンボリックリンクは拒否され、サイズの上限もあるので、紛れ込んだリンクや
  肥大化したディレクトリがコピーされることはありません。

### 日々の使い心地

- **プロキシ設定をコピー** で、プロキシ経由のルートの OpenAI 互換スニペットをクリップボードに入れ、他のツールも
  同じルートへ向けられます。
- **メニューバー / システムトレイ**に常駐し、ウィンドウを閉じてもプロキシは動き続けます。
- **7 つの表示言語**（English、简体中文、日本語、한국어、Français、Deutsch、Español）、ライト / ダーク / システム
  連動のテーマ、変更可能なキーボードショートカット。

## はじめに

### インストール

**macOS（Apple Silicon）は Homebrew でのインストールをおすすめします。**

```sh
brew install --cask rushteam/tap/aiopt
```

この cask は **AiOpt.app** を `/Applications` に置き、macOS の隔離フラグを消すので、初回起動時に Gatekeeper の
確認は出ません。`brew upgrade --cask aiopt` で新しいリリースに更新し、`brew uninstall --cask aiopt` でアプリを
削除します。`--zap` を付けると、保存済みのキーを含むデータも削除されます。

どのプラットフォームでも、ビルドを直接ダウンロードすることもできます。ビルドは各
[GitHub Release](https://github.com/rushteam/aiopt/releases) に添付されており、タグの付いたコミットから 3 つの
プラットフォームそれぞれでビルドされます。

| プラットフォーム | ダウンロードするもの | インストール方法 |
| --- | --- | --- |
| macOS | `.zip` | 解凍し、**AiOpt.app** を `/Applications` にドラッグします。 |
| Windows | `Setup.exe` | 実行するだけです。Squirrel がユーザー単位でインストールし、管理者権限の確認は出ません。 |
| Linux | `.zip` | 任意の場所に解凍し、`AiOpt` バイナリを実行します。 |

**macOS ビルドは現在 Apple Silicon（arm64）専用です。** Intel Mac ではソースから実行してください。

#### ビルドは未署名です —— まずこちらをお読みください

コード署名証明書がまだないため、**macOS と Windows はどちらも、ダウンロードしたビルドを初回起動時に拒否します。**
インストールごとに一度、意図的に乗り越える必要があるブロックです。Homebrew の cask ならこの手順を代わりに行います。

- **macOS** —— 最初にダブルクリックすると、「開発元を検証できないため、“AiOpt”は開けません」と表示されます。
  これを閉じてから、**アプリを右クリック（または Control キーを押しながらクリック）→ 開く** を選び、2 つ目の
  ダイアログで確定します。それでも macOS が拒否する場合は、**システム設定 → プライバシーとセキュリティ** を開き、
  AiOpt に関するメッセージまでスクロールして **このまま開く** をクリックします。
  代わりに AiOpt が **壊れているため開けません** と表示される場合は、[よくある質問](#よくある質問)を参照してください。
- **Windows** —— SmartScreen が青い「Windows によって PC が保護されました」画面を表示します。**詳細情報**
  をクリックしてから **実行** をクリックします。
- **Linux** —— アプリがブロックされることはありません。

これを行うのは、ファイルの入手元を信頼できる場合だけにしてください —— マルウェアもまったく同じ手順を求めて
きます。署名は予定されています（`docs/dev-rules/development-workflow.md` §6 を参照）。

### 初回の実行

AiOpt はエージェント CLI の設定とフォーマット変換を担うもので、それ自体がモデルと通信することはありません。

1. **プロバイダーを追加** —— プロバイダー → **プロバイダーを追加**。プリセットか **カスタム…** を選び、API キーを
   貼り付けて、使いたいモデルを読み込むか列挙します。キーは OS 暗号化シークレットストアに入ります。フォームを
   開き直すと、キーそのものではなく「キーは保存済み」と表示され、**表示** を押したときにだけ再び表示されます。
2. **エージェントをバインド** —— エージェントカードで **設定する** を選び、プロバイダーとモデルを選んで **適用**。
   AiOpt はそのエージェントの設定ファイル（`~/.claude/settings.json`、`~/.codex/config.toml` など）を、
   プロバイダーまたはローカルプロキシを指すように書き換えます。
3. **エージェントをいつもどおり使います。** 後から同じカードでいつでもモデルを切り替えられ、**デフォルトに戻す**
   でエージェントの設定を元どおりに返せます。

**AiOpt は他のツールに属する設定ファイルを編集します。** 書き込むのは `shared/aiProviders.ts` でエージェント
ごとに宣言された特定のファイルだけで、どれも先にバックアップを取りますが、あなたが手作業で設定したファイルかも
しれません。バインドする前に **設定を表示** で確認してください。

## よくある質問

### macOS で「“AiOpt”は壊れているため開けません。ゴミ箱に入れる必要があります。」と表示される

ファイルは壊れていません。ビルドは Apple Developer ID で署名されておらず公証も受けていないうえ、macOS は
ブラウザーでダウンロードしたものすべてに隔離（quarantine）フラグを付けます。そのため Gatekeeper がアプリを
拒否し、Apple Silicon と新しい macOS ではしばしば「壊れている」と表示されます —— **このまま開く** ボタンは
なく、右クリック → 開く でも回避できません。

**AiOpt.app** を `/Applications` に移動してから、ターミナルで隔離フラグを含む拡張属性を消します。

```sh
sudo xattr -cr /Applications/AiOpt.app
```

あとはいつもどおり開きます。それでも起動しない —— すぐに終了する、または再び壊れていると表示される —— 場合は、
アドホック署名を付け直してからもう一度試してください。

```sh
codesign --force --deep --sign - /Applications/AiOpt.app
```

これを行うのは、このリポジトリの [Releases](https://github.com/rushteam/aiopt/releases) ページから
ダウンロードしたものに限ってください。Homebrew でインストールした場合、この手順は不要です。ビルドが署名・公証
されれば、誰にとっても不要になります。

## 設計

### セキュリティこそがアーキテクチャ

AiOpt は API キーを預かり、ホームディレクトリのファイルを書き換えます。だからこそ、セキュリティモデルは後付けの
層ではなく、アーキテクチャそのものです。

- **UI は信頼しません。** 画面はサンドボックスとコンテキスト分離が有効で Node にアクセスできないレンダラーで
  動きます。最小限の preload は用途ごとに名前を付けたメソッドだけを公開し、メインプロセスの各 IPC ハンドラーは
  何かをする前に**送信元を確認し、次にペイロードを実行時に検証**します。
- **キーは OS が暗号化します。** Electron `safeStorage` を通じて、macOS ではキーチェーン、Windows では DPAPI、
  Linux では利用可能ならデスクトップのキーリングを使います。キーが UI、ログ、バージョン管理下のファイルに届く
  ことはありません。
- **プロキシはループバックだけで待ち受け**、各リクエストをルートトークンで認証し、本物のキーはアウトバウンドの
  リクエストにだけ入れます。上流のエラーボディは転送せず（キーをエコーしている可能性があるため）、ログには
  メソッド、パス、ステータス、バイト数だけを記録します —— ボディ、ヘッダー、トークン、キーは決して記録しません。
- **書き込みは狭く、元に戻せます。** 明示的な許可リストにあるエージェント設定ファイルにしか書き込めません。
  書き込みはすべてアトミック（一時ファイル + リネーム）で、一度だけバックアップを取り、失敗しても元のファイルは
  そのまま残ります。
- **フェイルクローズ。** 厳格なメイン側の CSP、ロックダウンした Electron Fuses とナビゲーションガード。壊れた
  レコードは信頼せず読み込み時に捨て、変換できないフィールドは拒否します。

### エンジニアリング

- **技術スタック：** Electron 41、React 19、TypeScript（strict）、Vite 6、Electron Forge、Vitest、pnpm workspaces。
- **可動部品は最小限。** プロキシは Node 標準の `http` モジュールで作られ、サードパーティーのプロキシや SDK に
  依存しません。変換器と SSE コーデックは純粋関数で、ネットワークなしでテストできます。
- **重要な境界をテスト** —— 変換器、ストリーミング、ルートトークン、設定アダプター、アトミックな書き込み、
  そして macOS・Windows・Linux のパス処理。リリースビルドは 3 つのプラットフォームすべてで実行されます。
- **ローカライズもゲートで管理。** UI の文言は i18n を通り、プロダクト用語は CI で裁定済みの用語集と照合されます。

## ソースから実行

Intel Mac や、ビルドが添付されていないプラットフォームでもこの方法を使います。Node 20 以上と pnpm が必要です。

```sh
pnpm install
pnpm dev                # open the app window
```

ソースから実行した場合、データはインストール版とは分けて、`AiOpt` ではなく `AiOpt-dev` に保存されます
（`~/Library/Application Support`、`%APPDATA%`、または `~/.config` の下）。プロバイダーが何もない状態で
起動し、インストール版アプリのキーを読むことも変更することもありません。両者を同時に実行できます。

## コントリビュート

コントリビューションを歓迎します。すべてのコミットに DCO の署名が必要です —— `pnpm dco:install-hook` を一度
実行すれば自動で付きます。`CONTRIBUTING.md` を参照してください。ルールの索引は `AGENTS.md`
（*「領域 X に触れる前にルール Y を読む」*）、コードベースの地図は `docs/dev-rules/repo-map.md` です。

| コマンド | 検査する内容 |
| --- | --- |
| `pnpm test:unit` | ワークスペースのすべてのユニットテスト（コミットのゲート）。 |
| `pnpm -r run --if-present typecheck` | パッケージごとの型チェック。 |
| `pnpm check:dco` | すべてのコミットに一致する DCO 署名が付いていること。 |
| `pnpm check:i18n-glossary` | UI の文言が裁定済みのプロダクト用語を使っていること。`GLOSSARY.md` が同期していること。 |
| `pnpm check:version` | 2 つのマニフェストが同じバージョンを示し、リリースタグと一致していること。 |
